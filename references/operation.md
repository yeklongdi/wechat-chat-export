# 运行参数与故障定位

## 安装位置

`scripts/setup.ps1` 默认把环境建在 `%LOCALAPPDATA%/wechat-chat-export/venv`，与 skill 源码分开。可通过 `-Python` 选择解释器，通过 `-CacheDirectory` 指定环境目录。普通导出只安装 `requirements.txt`；`-WithTests` 另外安装测试依赖并运行合成测试。

模块位于 `scripts/vendor/`。不要改用不明镜像或自动下载旧二进制来替换读取模块。

## 选择群聊或好友

```powershell
& $taskPython -B $taskExporter --list-chats '讨论'
& $taskPython -B $taskExporter --chat '项目讨论群' --minutes 60
& $taskPython -B $taskExporter --chat '张三' --all-history
& $taskPython -B $taskExporter --chat '12345@chatroom' --chat 'wxid_example' --minutes 60
```

名称和 ID 均为示例。`--list-chats [关键字]` 只查询联系人及消息表元数据，不查询正文，不生成文件；省略关键字则列出可识别的本机会话。候选包含 `name`、`type`（`group`／`private`）和 `username`，后者可直接传给 `--chat`。

`--chat` 优先精确匹配会话 ID，其次匹配完整群名、好友备注、昵称或微信号，名称匹配忽略大小写。名称重名或只有模糊匹配时返回 `status=needs_selection`、候选和退出码 2；选定准确 ID 后重试。联系人中存在但没有本机消息表的会话不作为可导出候选。无法映射的消息表数量会在列表结果的 `unmapped_table_count` 中报告；已知准确 ID 时仍可尝试显式指定。

联系人名称优先备注、昵称、微信号，无法解析时用原 ID。群内发言人通过各分片自己的 `Name2Id` 映射到联系人名称，不跨分片套用数字 ID；暂不读取群内专属名片。未知发送方保留本地 ID，计入 `unresolved_sender_count`。

可重复 `--chat` 选择多个会话，每个会话分别写出文件。省略会话参数仍默认文件传输助手，兼容旧调用。无需进行任何转发。

## 选择时间和输出目录

- `--minutes N`：以脚本开始时刻为结束，向前 N 分钟；N 必须为正整数。省略时默认 60。
- `--start ISO --end ISO`：明确的左闭右开时间窗。
- `--start ISO`：从指定开始时间至执行时刻。
- `--all-history`：所选会话在本机保存的全部历史，时间窗从 Unix 起点至执行时刻；不能和 `--minutes`、`--start`、`--end` 混用。
- 时间不含偏移时按 UTC+08:00 解释；包含偏移时保留其实际时刻，输出统一为北京时间。
- `--output-root PATH`：在该目录下创建带时间和随机后缀的新目录，避免覆盖旧结果。默认是用户目录下的 `Documents/WeChat Exports`。

先验证参数，再读取任何本地微信内容。`--end` 不能单独使用，也不能与 `--minutes` 混用。

## 账号与版本

默认从微信本地配置定位 `xwechat_files`。若没有自动定位成功，可传入：

```text
--db-dir D:\WeChatData\xwechat_files\已选择的账号目录\db_storage
```

这是目录结构示意，实际路径以用户设备为准。存在多个账号目录时不要静默选择第一个；根据用户给出的账号确认路径，再传 `--db-dir`。

实时读取需要正在运行且已登录的 `Weixin.exe`。读取模块先尝试 Windows 4.1+ 的运行时对象扫描，再尝试旧版的只读扫描。主程序不调用 `capture-experimental`，也不调用第三方工具的默认文件写出流程。

## 成功与受限结果

联系人库及每个非空消息分片必须完成材料校验、已提交 WAL 合并、全部页 HMAC 认证以及 SQLite `quick_check`。程序先建立会话目录，解决名称歧义，再只查询选定会话的表和时间窗。逐个分片打开以限制内存占用，目录检索与正文读取分别取得快照。未获得某个分片的材料时中止，不能把其余分片当作完整导出。

联系人库不存在时，可使用可识别的原会话 ID，列表结果标注 `contacts_available=false`；联系人库存在但材料缺失、结构不符或认证失败时应中止。多人同名、缺少本机消息表或无匹配时间记录不应触发其他会话的全文读取。

合并转发必须包含可解析的 `recorditem`，声明条数与实际条数必须相同。TXT 应包含每一条正文及引用，JSON 需能重新读取并得到相同数量。

`status=complete` 表示上述范围内的处理和最终文件检查完成。空结果表示本机在该窗口内没有匹配消息，不代表其他设备没有记录。只有卡片预览、缺少转发明细或解析失败时不能声称完整展开。

## 常见失败

| 现象 | 处理 |
|---|---|
| 找不到微信数据目录 | 核对数据存放位置，使用明确的 `--db-dir` |
| 检测到多个账号 | 让用户选择目标账号，不导出其他账号 |
| 名称重名或仅有模糊匹配 | 从候选中选定目标，再用准确会话 ID 导出 |
| 没有找到指定群名／好友 | 先搜索会话列表；检查记录是否已同步至电脑、名称是否变化 |
| 没有可验证材料 | 核对登录状态、账号路径、权限与客户端版本 |
| 页认证或 SQLite 检查失败 | 保留失败说明，先核对格式及版本适配 |
| 主库与 WAL 持续变化 | 微信空闲时重试一次，仍不稳定则报告受限 |
| 转发条数不一致或缺少明细 | 明确指出该条记录未完整解析，不能只交付预览摘要 |
| 目录权限设置失败 | 在写入聊天文件前停止，使用用户可写的位置 |

真实数据库、密钥和正文不用于测试或公开问题复现。提交问题时提供版本、状态和错误类别即可。
